# Ablation study: чотири паралельні сценарії

## Файли запуску

- `run_cf_vote.py` — повний простір генів + зважене Soft Voting RF/XGB.
- `run_cf_stack.py` — повний простір генів + OOF stacking RF/XGB.
- `run_cl_vote.py` — кластерні підпростори + дворівневе зважене Soft Voting.
- `run_cl_stack.py` — зважені локальні ансамблі + OOF Cross-Cluster Stacking.
- `ablation_common.py` — спільна перевірена логіка, щоб чотири сценарії не
  дублювали код.

## Нормалізація

Збережено погоджений протокол: `StandardScaler.fit_transform()` застосовується
до повної TCGA-матриці до розділення `70/30`. Кожна зовнішня validation-матриця
нормалізується незалежно. Для кластерних матриць використовуються ті самі
індекси train/test.

## Stacking

Метамодель — багатокласова `LogisticRegression`. Вона навчається виключно на
OOF-імовірностях, сформованих у межах TCGA training subset. Параметр `C`
метамоделі окремо оптимізується Bayesian Optimization. Test та validation не
використовуються ні для оптимізації, ні для навчання метамоделі.

## Визначення ваг

У сценаріях із голосуванням ваги RF та XGBoost у кожному просторі ознак
визначаються пропорційно до найкращого `CV Weighted F1`, отриманого під час
байєсівської оптимізації на TCGA training subset:

`alpha_q = Q_q / sum(Q)`.

Для кожного кластерного підпростору локальний ансамбль додатково оцінюється за
OOF-прогнозами навчальної вибірки. Міжкластерні ваги обчислюються за правилом:

`v_k = (p_k * Q_k_OOF) / sum_j(p_j * Q_j_OOF)`,

де `p_k` — кількість генів у кластері, а `Q_k_OOF` — `Weighted F1` локального
зваженого ансамблю на OOF-прогнозах. Test і validation не використовуються для
обчислення ваг.

У `CF_VOTE` існує лише один простір генів, тому структурний множник за кількістю
генів після нормалізації дорівнює одиниці; застосовуються лише CV-ваги RF/XGB.

У `CL_STACK` локальні RF/XGBoost-імовірності також об'єднуються за CV-вагами.
Подальше об'єднання кластерів виконує справжня OOF-метамодель, оскільки саме
заміна другого рівня голосування на stacking є компонентом цього абляційного
сценарію. Розраховані структурно-якісні ваги зберігаються у
`weighting_info.json` для контролю, але до stacking-метамоделі не застосовуються.

## Перед запуском

1. Помістіть папку `Common_genes` і чотири кластерні CSV у корінь проєкту або
   скоригуйте шляхи на початку запускних файлів.
2. Встановіть залежності:

   `pip install numpy pandas scikit-learn xgboost bayesian-optimization joblib`

3. Створіть чотири PyCharm Run Configurations з відповідними файлами.
4. Робоча директорія для кожної конфігурації — каталог `ablation_study`.

Кожний сценарій використовує `n_jobs=12`; чотири паралельні процеси займають до
48 потоків із 64, залишаючи резерв системі. Не встановлюйте `n_jobs=-1` при
одночасному запуску.

Для короткого технічного тесту тимчасово задайте у запускному файлі:

`Settings(n_jobs=12, init_points_rf=2, n_iter_rf=3,
init_points_xgb=2, n_iter_xgb=3, init_points_meta=2, n_iter_meta=3)`

Після перевірки шляхів і пам'яті поверніть повний бюджет.
